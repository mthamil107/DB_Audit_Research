# RESULTS — Self-Defeating Audits — SQL Server (LocalDB)

_Local, synthetic lab. Generated by `run_matrix_mssql.sh`. Low-privilege attacker modelled
via `EXECUTE AS USER='app_user'` (LocalDB is Windows-auth only); permission checks are
enforced in that user's context._

## Environment

| Field | Value |
|---|---|
| Engine | SQL Server LocalDB |
| `ProductVersion` / Edition | 17.0.925.4 Express Edition (64-bit) |

> The SQL Server "definer" analogue is **ownership chaining** (trigger, business table, and
> audit table co-owned by `dbo`), so a low-privilege writer is audited without any direct
> grant on the audit table. SQL Server has **no `search_path`**; the PG 1A/1B class does not transfer.

## Defenses

| Defense | Result |
|---|---|
| Remove ALTER on the table from app | app_user without ALTER on the table cannot DISABLE/replace the trigger (denied) → write still logged (DPRIV logged=1) |
| DDL-trigger guard (detection) | DDL trigger catches ALTER (DDLGUARD alter_caught=1) but NOT DISABLE/ENABLE (DDLGUARD disable_caught=0) — DISABLE raises no DDL event (detection gap) |
| Hash-chained append-only sink | HC intact=NULL; HC tampered=4 (non-NULL seq = tamper detected) |
| SQL Server Audit (engine-level) | recommended engine-level control (server/db audit to file/security log, outside the app principal's reach); not scripted on LocalDB |
